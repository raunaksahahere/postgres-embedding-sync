# Guarantees and how they are tested

| guarantee | mechanism | evidence (`test/integration`, real PostgreSQL 16/17/18) |
|---|---|---|
| No lost or duplicated effects across crashes | effects + checkpoint LSN in one sink transaction; units at or below the checkpoint are skipped; feedback reports only the durable LSN | `TestFailpointCrashes` (kill exactly before sink commit and after commit before feedback, 4 crashes each, concurrent writers, then full verify); `TestConcurrentWritesAbortsAndKills` (SIGKILL loop under 4 writers with ~20 % aborted transactions) |
| Feedback never ahead of durable progress, also on keepalives | status updates carry the durable LSN only; idle positions go through the committer | `assertFeedbackNotAhead` after every crash (slot `confirmed_flush_lsn` ≤ checkpoint); `TestIdleProgressAndState` (checkpoint advances on unpublished WAL) |
| Aborted transactions have no effect | pgoutput only delivers committed transactions; the planner never applies partial ones | concurrent writer tests with rollbacks |
| Zero missing, extra or stale chunks | deterministic chunk IDs, fingerprints, trim of obsolete chunks, range deletes in backfill windows | `embedsync verify` after every scenario compares every row's expected chunks (content + fingerprint) with the sink at one barrier |
| Backfill under concurrent writes never resurrects deletes or keeps stale rows | watermark windows; snapshot rows yield to stream changes inside the window; range delete with keep set | `TestBackfillDuringWrites` (2,500 rows, 37-row windows, 4 writers, deletes, key changes); property test `TestPropertyBackfillInterleavings` (1,000 random interleavings incl. TOAST deferrals and window discards, mutation-checked) |
| Truncate | stream truncate clears state and every live generation in the unit | `TestStreamCorrectness` |
| Only allowlisted columns leave the source | publication column list + column-level grants + explicit SELECT lists | `TestLeastPrivilegeAndColumnAllowlist` (secret column never reaches sink, metrics or logs; reader role cannot read `source_state`) |
| Unchanged TOAST values | filled from `source_state`, deferred to backfill, or pause | `TestUnchangedToast` (45 KB body, title-only updates, key change) |
| Embedding outage loses nothing | retries with jittered backoff; nothing acknowledged | `TestEmbeddingOutage` |
| Poison rows | quarantine atomically with versioned DLQ records, newer edits/deletes supersede, replay respects them; or pause | `TestPoisonQuarantineAndReplay` |
| Incompatible schema change is never acknowledged | relation signature check in the stream and at startup | `TestSchemaChangePauses` |
| Slot loss is detected and recoverable | identity checks; `rebuild` into a fresh generation | `TestSlotLossRebuild` |
| Several tables share one slot without losing transaction boundaries | one reader, planner and committer for every pipeline; a unit holds whole source transactions and commits only after all of its embeddings, in LSN order | `TestCrossTableTransactionBoundary` (a transaction updates a document and a ticket; one embedding is held back 250 ms, alternating tables; a concurrent reader samples both tables in one snapshot throughout (at least 50 samples required; ~850 per run observed) and never sees mismatched versions); `TestMultiPipelineAcceptance` |
| Overlapping ids and composite keys stay separate documents | identity is `(pipeline, encoded key)`; a composite key is a JSON array of its column values, a one-column key its value | `TestMultiPipelineAcceptance` (three tables, ids overlap across two of them, `(tenant_id, id)` key changes, deletes during backfill, 6 crashes before/after the sink commit, every pipeline verified at a barrier); `keys` unit tests (escaping, invalid UTF-8 rejected) |
| Composite-key backfill windows agree with PostgreSQL | row comparison over the typed key columns (text with `COLLATE "C"`) in the source scan; the same lexicographic order in Go and in the sink's range deletes | `TestCompositeKeyOrderAgreesWithPostgres` (negative ints, mixed case, UTF-8, digits as text, JSON-escaped characters; 5-row scan windows, 200 random sink ranges and an end-to-end backfill with 3-row windows); 3-pipeline property test (1,000 interleavings, mixed-table transactions, per-table truncates) |
| Upgrading a populated single-table installation | `init` labels every existing row with the pipeline `default` and keeps fingerprints; commands refuse an un-upgraded sink | `TestLegacyUpgradeServesOriginalDocuments` (installation built by v0.2.0 with two generations and DLQ records: no re-embedding, identical chunks and search results, replay and rollback still work, then a composite-key table added in place) |
| View documents are consistent with the transaction being applied | every view table's rows go to `source_state` and the references to `source_refs` in the same sink transaction as the checkpoint; planning reads the overlay of uncommitted units over the sink, never the source; each dirty document is rendered once at the end of a unit | `TestViewAcceptance` (2 tenants with overlapping ids, 12 documents each; a section moved between documents, a tag renamed (only the tenant's linked documents change), links and a parent deleted, one 7-statement transaction yields one document written once at that transaction's position, quarantine and replay, migration to a second model; every step compared with documents assembled from the source with SQL joins); `TestViewWritesBackfillAndCrashes` (3 tenants, 40 documents each, 3 writers on every view table incl. section moves, key changes and ~20 % rollbacks during the state and render backfills, 6 crashes before and after the sink commit, a TOASTed section edited without its body, a truncated child table, then full verify) |
| A transaction that changes too many documents is never half applied | per-view count of documents changed by one source transaction; above `max_fanout_per_txn` the pipeline pauses before acknowledging | `TestViewFanoutLimitPauses` (a tag shared by 60 documents against a limit of 40: state `paused:fanout_limit`, no chunk written, checkpoint unchanged, feedback not ahead; after raising the limit to 100 all 60 documents carry the new name) |
| Upgrading a populated v0.3.0 installation to views | `init` applies `sink/0003_views.sql` (additive); commands refuse an un-upgraded sink | `TestUpgradeFrom030AddsView` (installation built by v0.3.0 with three pipelines: after `init` zero inputs are embedded and the chunks are unchanged; a view is then added in place, backfilled (state, render and embed jobs) and verified in every generation) |
| Model migration is pinned, gated, atomic and reversible | per-generation encoder identity; gates at one snapshot; serving row swap; rollback window | `TestMigrationPromoteRejectRollback` (continuous reader: zero errors, zero wrong results, generation sequence v1→v2→v1; regression rejected with an inspectable report); `TestMigrationResume` |
| Provider faults are retried, never quarantined, never acknowledged early | retries with jittered backoff; HTTP 429 waits at least the capped `Retry-After`; connection errors, 5xx, malformed or invalid responses are transient; nothing is acknowledged until its effects are durable | `TestProviderFaultsAndCheckpointSafety` (throttling, an outage, malformed batches, and crashes before and after the sink commit while throttled: feedback never ahead of durable progress, checkpoint advances after the outage, zero DLQ records, full verify); unit tests `TestOpenAIThrottled`, `TestOpenAIOutage`, `TestOpenAIMalformedResponses` in `internal/embedclient` |
| Throttling honours `Retry-After` | the retry wait is at least the server's request, capped by `max_retry_after` | `TestProviderRetryAfterIsHonoured` (three 429s with `Retry-After: 1`: at least three throttled retries, at least 3 s waited, the edit searchable afterwards); unit tests `TestParseRetryAfter`, `TestOpenAIThrottled` |
| A refused input is quarantined alone; a provider-wide failure never quarantines | a multi-input batch refused with 400, 413 or 422 is bisected; a single refused input is quarantined only once the provider is known to work (an earlier valid response or a known-good probe request), otherwise it is a configuration or account error (e.g. an invalid key); 5 consecutive invalid responses isolate the inputs responsible, and if every input is affected (e.g. a wrong configured dimension) the error is permanent; nothing is quarantined for a provider-wide failure | unit tests `TestOpenAIBisectsPoisonInputs`, `TestOpenAIRequestWide400IsPermanent`, `TestSingleRefusedInputQuarantinedAfterProbe`, `TestPersistentlyInvalidResponses` |
| Vectors from different providers or request dimensions never share fingerprints | non-local chunk fingerprints include provider name, kind, request dimensions and document input type; local fingerprints are unchanged | unit test `TestFingerprintProviderIsolation` in `internal/transform` |
| Queries use the searched generation's provider across promotion and rollback | the generation records its provider and request settings; search embeds with that provider; the gate report names both providers | `TestCrossProviderMigrationGate` (promotion to a model served by the mock provider: search reports `mock`; a regressing candidate is rejected and serving is unchanged; rollback returns search to `local`; a continuous reader sees zero errors and zero wrong top-1 results; both generations stay in the rollback window; identity `mock/openai` recorded) |
| Real endpoints use the same code path as the mock | the same code paths against real servers; each endpoint runs only when its environment variable is set and is reported as not verified otherwise | `TestRealProviderThroughput`, `TestRealCrossProviderMigration` (`RUN=TestReal scripts/test-integration.sh 17`), gated by `EMBEDSYNC_IT_CPU_EMBEDDER_URL`, `EMBEDSYNC_IT_GPU_OPENAI_URL`, `GEMINI_API_KEY`; run for the built-in CPU embedder, Ollama on an AMD GPU (ROCm) and the Gemini free tier, with the gate results in the README; OpenAI, NVIDIA, CUDA GPUs and paid tiers were not run |

| Filters, text and hybrid search return exactly the matching documents | filters compile to bound parameters over the chunk metadata, one restriction per branch; missing fields fail every comparison except `not`; fused ranks follow RRF | `TestSearchFiltersHybridAcceptance` (every filter operator against SQL on the source: eq, ne, in, range, contains, exists, timestamps, `or`, `not` including documents without the field; an exact identifier first in text and hybrid; a paraphrase found only by the vector branch; a metadata-only update changes results with zero embedded inputs; the 400 and 404 error codes and fields; the response fields are checked against `api/openapi.yaml`); unit tests in `internal/filter` and `internal/search` |
| A tenant never sees another tenant's chunks | the tenant predicate is added to every branch from the gateway header; a filter on the tenant field is refused | `TestSearchTenantScope` (missing header refused, forced on vector, text and hybrid, a client filter cannot widen it, a GET with the header sees only its own tenant, an unknown tenant sees nothing) |
| A search answers from one generation and one snapshot | the generation and its encoder are pinned in one repeatable-read transaction; a promotion between embedding and querying re-embeds the query for the new generation | `TestSearchPinnedAcrossPromotion` (a pinned search and a fresh v1 search agree during a promotion); the hybrid branches share one transaction |
| Upgrading a populated v0.5.0 installation builds the search columns without re-embedding | `init` applies `sink/0005_search.sql` (additive); `run` fills the columns from stored content and re-scans only pipelines and views with metadata, reusing stored vectors; filtered, text and hybrid requests answer `503 search_index_building` until ready | `TestUpgradeFrom050BuildsSearchColumns` (installation built by v0.5.0 with documents in two pipelines: legacy GET answers identically throughout, no input is embedded during the build, filtered requests answer 503 with `Retry-After` until ready, and the chunks keep their keys, fingerprints and vectors) |

What is **not** guaranteed:

* Search results are eventually consistent with the source: a committed row is
  searchable after the measured commit-to-searchable latency, not at commit.
* A paused pipeline (schema change, poison row with `on_poison: pause`, unresolvable
  TOAST) stops freshness for every table, because all tables share the stream and their
  transactions are applied in order, until an operator acts; WAL accumulates meanwhile
  (bounded by `max_slot_wal_keep_size`).
* Quarantined rows are absent from search until resolved (by design: never serve an
  outdated version), and are reported as unresolved.
* A pipeline's document is one row of one table. Only views assemble documents across
  tables: one level of children and links to one target table, within one tenant.
  There is no other join, and a table cannot be in two pipelines or views.
* A view document that exceeds `max_children` is quarantined, not truncated.
* Metadata changes are eventually consistent, like the text: a filter sees a changed value
  after the same freshness latency. A generation whose search columns are not complete
  refuses filtered, text and hybrid requests (503) rather than answering from partial
  metadata.
* Filtered vector search on pgvector older than 0.8 can return fewer than `k` hits
  (`exact: false`); `exact: true` is exact at the cost of a sequential scan.
* The tenant header is trusted, not verified. Protecting the tenant boundary is the
  gateway's job, not embedsync's.
